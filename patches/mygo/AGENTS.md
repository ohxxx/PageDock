# MyGo Windows patches

MyGo 0.5.1 hidden-title-bar buttons read only the app/system theme, causing dark glyphs on dark pages when their colors differ. Shared color/file algorithms stay here. `windows/changes.go` defines target patches and `windows/permissions.go.in` contains the native template. Tests live under `tests/patches/mygo/`. `tools/mygo-patch/main.go` copies the pinned dependency into `.cache/mygo-patch/` at build time; patches change Windows behavior only:

- `titlebar.go`: For opaque window backgrounds, choose black/white glyphs by sRGB relative luminance. Without an explicit opaque background, retain MyGo's theme selection.
- `window.go`: Redraw existing buttons after SetBackgroundColor. Existing code still handles hover, pressed state, the red close background, focus, scaling, and Snap Layout.
- `color.go`: One color function shared by production copies and tests; no separate button interaction implementation.
- `tests/patches/mygo/color_test.go`: Light/dark pages, settings colors, mid-gray boundaries, and colored backgrounds.
- `updater/cleanup.go`: Copied into the MyGo root package and called by updater.go's Windows branch through the existing App.Run background cleanup entry. Resolve the launch path consistently with EXE appearance transactions. Handle only same-directory .<current filename>.old-* regular files. Snapshot candidates at startup and retry every 100ms for up to 15 seconds. Retain/log timed-out files for later launches; never delete recovery copies, directories, links, or another EXE's old files.
- `tests/patches/mygo/updater/cleanup_test.go` / `tests/patches/mygo/updater/windows/cleanup_test.go`: Real temporary-file scope, busy-file retries, timeout retention, and later launches. Windows additionally runs/renames a temporary test EXE and verifies deletion after its image lock releases.
- `surface.go` / `menu.go`: Dispatch matching menu shortcuts before native Surface UI controls handle keyboard messages, then consume the message. Fix Ctrl+, doing nothing and Ctrl+V pasting twice. Check disabled menu state before dispatch. Real Win32-message/clipboard tests live in tests/internal/windows/window_test.go.
- `windows/permissions.go.in`: Copied as backend Go source. Set SavesInProfile=false so each permission request is evaluated by the app. Before first navigation, ICoreWebView2Profile4 enumerates/removes legacy camera, microphone, geolocation, and notification decisions, including grants and denials. Preserve all other permissions and website data. Queue navigation until migration completes, block loading on failure, and cancel/release COM references on destruction. Requires WebView2 Runtime 1.0.1661.34 or newer.
- `dialog.go`: Legacy MessageBoxW honors DefaultID through named MB_DEFBUTTON offsets. PageDock cleanup confirmations place the affirmative choice first and cancel last to match MyGo's legacy result mapping. Both modern TaskDialog and legacy dialogs default to cancel.

Do not change global/system themes, website prefers-color-scheme, or the module cache. macOS/Linux retain the pinned version's original backends. Go builds disallow module-cache overlay changes, so use the separate dependency copy and temporary modfile; never edit $GOMODCACHE directly.

`make dev/test/test-desktop/check/build/build-windows` prepares patches automatically. Direct Go tests also require the -overlay produced by tools/test-overlay; see tests/AGENTS.md. Bare test commands miss centralized tests. Run `go run ./tools/mygo-patch` first and pass its output as -modfile or GOFLAGS to direct Go commands. Windows builds bypassing these entries lack the fixes.

Abort on version/context mismatch. When upgrading MyGo, check whether upstream fixes replace these patches, then remove superseded patches/preparation instead of adding alternate button implementations. Cache files are rebuildable outputs; patch sources stay in the repository.

`make test TEST_ARGS='-run TestCaption -count=1'` checks color selection. On Windows, `make test-desktop` also runs TestDesktopWindowsCaptionFollowsPage with isolated windows and actual screen-button pixels. It requires an interactive desktop with unobscured test windows. macOS tests or cross-compilation do not prove Windows screen behavior.

Old-EXE cleanup: `make test TEST_ARGS='-run TestUpdateCleanup -count=1'`. Real Windows process locks: `make test TEST_ARGS='-run TestWindowsUpdateCleanup -count=1 -timeout=30s'`. Other platforms run file tests without invoking Windows startup code. Never retain upstream's broad recursive .*.old-* deletion as a parallel cleanup path.

For media permission tests, run `node tests/playground/windows/media.mjs` on Windows. It creates temporary audio/video files, isolates the WebView2 profile, runs TestDesktopWindowsMediaPermissionRecovery, and removes this run's temporary data. A precompiled desktop test EXE may be supplied. Replace device inputs only; never use --use-fake-ui-for-media-stream to bypass real permission callbacks. Ordinary desktop runs skip the case without explicit sources, avoiding automatic physical-device access. Validate legacy-cache migration separately in the packaged app and verify Cookie/localStorage retention. Test sources do not replace physical camera/microphone acceptance.
